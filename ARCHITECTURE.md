# Архитектура МФМ — публичный уровень

Этот документ показывает только продуктовые границы. Он намеренно не описывает внутреннюю инфраструктуру, защитные механизмы, адреса окружений и эксплуатационные процедуры.

## Общая модель

```text
                         ┌─────────────────────────┐
                         │ Финансовый цикл МФМ    │
                         │ расчёты · команды · UI │
                         └────────────┬────────────┘
                                      │
                     ┌────────────────┴────────────────┐
                     │                                 │
          ┌──────────▼──────────┐           ┌──────────▼──────────┐
          │ Personal / Wikmiks │           │ Corporate / ProKopa│
          │ без Подотчёта      │           │ Подотчёт + кейсы   │
          └──────────┬──────────┘           └──────────┬──────────┘
                     │                                 │
          ┌──────────▼──────────┐           ┌──────────▼──────────┐
          │ Локальное хранение │           │ Серверное хранение │
          │ в браузере         │           │ + изоляция учёток  │
          └─────────────────────┘           │ в пилоте           │
                                            └─────────────────────┘
```

Обе редакции решают задачи одного личного финансового цикла. Corporate расширяет модель Подотчётом и кейсами, но не превращает приложение в коллективную учётную систему.

## Personal / Wikmiks

- облегчённая редакция без Подотчёта;
- пользовательское состояние хранится локально в браузере;
- данные Corporate с неподдерживаемыми возможностями не должны незаметно превращаться в Personal;
- редакция рассчитана на одного человека и его личный зарплатный цикл.

## Corporate / ProKopa

- полная редакция с Подотчётом и кейсами;
- кейс имеет нейтральный код, например `К-009`;
- подтверждён ограниченный пилот учётной записи владельца и до пяти приглашённых учёток;
- каждая учётка хранит отдельное финансовое состояние и не видит данные других учёток;
- активированная приглашённая учётка не имеет автоматического срока окончания, но владелец пилота может отключить её вручную;
- эта возможность не является общим кабинетом организации и не даёт совместный доступ к данным.

## Инварианты публичного позиционирования

1. Personal не включает Подотчёт.
2. Corporate включает Подотчёт и кейсы.
3. Серверное сохранение и приглашённые учётки относятся только к ограниченному пилоту ProKopa.
4. Общедоступная саморегистрация, совместный кабинет, общий доступ к данным и бухгалтерия не заявляются реализованными.
5. Корпоративная адаптация выполняется только по согласованному процессу и техническому заданию.
6. Эта схема не является описанием production-инфраструктуры или гарантией будущих функций.
