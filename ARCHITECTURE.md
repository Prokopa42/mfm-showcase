# Архитектура МФМ — публичный уровень

Документ показывает продуктовые границы без внутренних адресов, секретов и эксплуатационных процедур.

## Общая модель

```text
                    ┌────────────────────────────┐
                    │ Расчётный контур МФМ      │
                    │ цикл · платежи · долги    │
                    │ накопления · сверки       │
                    └─────────────┬──────────────┘
                                  │
                 ┌────────────────┴────────────────┐
                 │                                 │
       ┌─────────▼──────────┐            ┌─────────▼──────────┐
       │ Личный режим      │            │ Личный + рабочие   │
       │ только свои деньги│            │ деньги и кейсы     │
       └─────────┬──────────┘            └─────────┬──────────┘
                 │                                 │
       ┌─────────▼──────────┐            ┌─────────▼──────────┐
       │ Локальное хранение│            │ Локальное хранение│
       │ серверный пилот   │            │ + серверный пилот │
       │ готовится         │            │ до 5 учёток       │
       └────────────────────┘            └────────────────────┘
```

Оба режима используют одно расчётное ядро. Дополнительный режим не меняет личную финансовую модель, а добавляет отдельный слой рабочих денег.

## Почему рабочие деньги находятся рядом с личными

Фактический остаток на карте или наличными может одновременно содержать свои и подотчётные средства. Поэтому система показывает общий физический остаток, но не смешивает источники в расчётах:

```text
Всего на руках = Свои деньги + Рабочие деньги
```

Только свои деньги участвуют в личном дневном лимите. Рабочие деньги, компенсации и обязательство вернуть подотчёт остаются видимыми отдельными величинами.

## Личный режим

- один личный зарплатный цикл;
- без подотчёта и рабочих кейсов;
- локальное хранение в браузере работает;
- запросы на пилотный доступ принимаются;
- отдельный серверный контур до пяти изолированных учёток готовится.

## Режим с рабочими деньгами

- все функции личного режима;
- подотчётные деньги, кейсы, траты, возвраты и компенсации;
- нейтральный «Код кейса», например `К-009`;
- подтверждён ограниченный пилот до пяти приглашённых учёток;
- каждая учётка хранит отдельное состояние и не видит данные других пользователей;
- общий кабинет организации и совместный доступ пока не реализованы.

## Технические названия окружений

Два серверных экземпляра имеют внутренние кодовые названия `Wikmiks` и `ProKopa`. Они нужны для конфигурации и изоляции окружений, но не являются пользовательскими названиями продукта.

## Будущая корпоративная сетка

Проектируемое направление предполагает индивидуальные рабочие контуры сотрудников и руководителей, сводное представление для финансового блока и согласованную выгрузку в таблицы. Эта схема потребует отдельной модели ролей, доступа, подтверждений, аудита и интеграций.

Она не считается реализованной частью текущего пилота.

## Инварианты публичного позиционирования

1. Личный режим не включает рабочие подотчётные деньги.
2. Дополнительный режим включает подотчёт и кейсы, но не увеличивает личный лимит рабочими деньгами.
3. Заявки принимаются для обоих режимов, но серверный пилот личного режима ещё готовится.
4. Общедоступная саморегистрация, общий кабинет, бухгалтерия и совместный доступ не заявляются готовыми.
5. Корпоративная адаптация выполняется по согласованному процессу и техническому заданию.
